# Подготовка GitHub-репозитория eurobot-next

Проверка подключённого GitHub-аккаунта vladromenko не нашла доступного репозитория по запросу `eurobot-next in:name`; у локального проекта remote отсутствует. Это граница доступа поиска, а не утверждение об отсутствии чужих или недоступных репозиториев. Новый публичный репозиторий не создавался и код никуда не отправлялся. Причина — неустановленные права на распространение производных результатов анализа исходников 2025/2026. Пользователь прямо запретил такую публикацию без подтверждения прав. Исходное приложение в новое дерево не копируется; проверяемая реализация, конфигурация CI и документация подготовлены локально.

Лицензия собственного кода пока не назначена: см. LICENSE-STATUS.md. Технический аудит не заменяет решение правообладателя. После его получения добавить подходящий LICENSE и настоящие maintainer сведения в ROS package.xml; сейчас использован явно недоставляемый example.invalid, чтобы не выдумывать контакт. Сторонние библиотеки загружаются tools/dependencies.sh из официальных репозиториев по проверяемым commit SHA; их notices сохранены. firmware/third_party, build, artifacts, резервные копии и локальные профили сборки исключены из Git.

Проверка перед публикацией:

```sh
python3 tools/audit_sources.py --legacy-root ..
python3 tools/audit_sources.py --publication
```

Второй режим намеренно завершится ошибкой, пока отсутствует LICENSE. Проверены распространённые токены/ключи и совпадения файлов с legacy Core; необходим также ручной просмотр протоколов, конфигураций и персональных данных. Локальные validation logs могут содержать пути компьютера, поэтому artifacts/ не публикуется.

После подтверждения прав и успешных проверок:

```sh
git add .
git commit -m "Implement Eurobot Next controller platform"
gh repo create eurobot-next --public --source=. --remote=origin --push
```

Создание remote и push приведены для последующего этапа с подтверждёнными правами. Локальная история сохраняется отдельно; внешняя публикация не выполнялась. CI настроен для host C++23/sanitizers/clang-format/static analysis, STM32F407 и ROS Jazzy/Lyrical. Успешное выполнение CI в GitHub не заявляется: workflow ещё не запускался удалённо. Готовность конкретного робота отслеживается отдельно в FUNCTIONAL_COVERAGE.md и KNOWN_ISSUES.md.


Текущий программный срез зафиксирован одним начальным локальным коммитом после свежих53/53 CTest в трёх режимах, Debug/Release/C++26 ARM и обоих ROS builds. Последующие изменения лицензии/maintainer/deployment должны оформляться новыми коммитами; проверенные образы и приватные профили не включаются в Git. Актуальный local HEAD можно посмотреть `git log -1 --oneline`; публичного remote нет.
