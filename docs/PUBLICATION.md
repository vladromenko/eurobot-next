# Репозиторий EUROBOT NEXT

Исходники опубликованы в репозитории владельца: [vladromenko/eurobot-next](https://github.com/vladromenko/eurobot-next). Репозиторий открыт для чтения; единственная финальная ветка — `main`. GitHub remote `origin` настроен на этот адрес.

В Git включены собственный код C++23, CMake, ROS2 workspace, профили, тесты, инструменты, документация и история разработки. Старое прикладное C-приложение2025/2026 не копировалось в новый репозиторий. `build/`, `artifacts/`, `backups/`, `firmware/third_party/`, локальные профили `*_local.hpp`, готовые ZIP/BIN и кэши исключены. Собранный комплект остаётся локально у владельца; после clone зависимости и образы получают воспроизводимой сборкой.

Перед отправкой проверены SHA256164 оригинальных справочных файлов, происхождение зависимостей и распространённые форматы секретов в текущем дереве и всех274 исторических Git-blobs. Совпадений с шаблонами ключей/токенов не найдено; это техническая проверка, не абсолютная гарантия отсутствия чувствительных сведений. Локальные backupFlash и журналы с системными данными не отправляются.

```sh
git clone https://github.com/vladromenko/eurobot-next.git
cd eurobot-next
bash tools/dependencies.sh
cmake --preset host
cmake --build --preset host
ctest --preset host --output-on-failure
```

Для чтения и клонирования авторизация GitHub не требуется. Подготовка и установка: [WHAT_I_NEED_TO_DO.md](../WHAT_I_NEED_TO_DO.md). Проверенные локальные результаты: [VALIDATION_REPORT.md](VALIDATION_REPORT.md). GitHub Actions настроен, но наличие workflow не означает успешный удалённый прогон; его фактическое состояние нужно читать в Actions.

## Лицензии и дальнейшее распространение

Лицензия собственного проекта не назначена: [LICENSE-STATUS.md](../LICENSE-STATUS.md). Публичная видимость исходников сама по себе не выдаёт разрешение на изменение, повторное распространение или коммерческое использование; лицензии сторонних компонентов приведены отдельно.

FreeRTOS/CMSIS/STM32F4 device загружаются по закреплённым commitSHA из официальных репозиториев через tools/dependencies.sh; копии notices сохранены в docs/vendor_licenses. Перед выдачей разрешений третьим лицам нужно выбрать лицензию и заменить maintainer example.invalid в ROS package.xml реальными контактами. Технический audit этого решения не заменяет.
