# Готовый профиль робота2026 и самостоятельная установка

Профиль [robot_2026.hpp](../firmware/include/eurobot/robot_2026.hpp) заполняет конфигурацию из имеющихся исходников, верхнего уровня и карты платы. Его пример [examples/robot_2026.hpp](../examples/robot_2026.hpp) уже включён в preset `stm32-robot2026`. Пустой deployment вручную заполнять не нужно. Это конфигурация для исходного робота2026 с предписанной новой проводкой8+8; испытание на настоящем роботе остаётся отдельным этапом.

`commissioned=true` в этом отдельном профиле означает выбранную полностью заполненную программную конфигурацию по исходникам, а не пройденную аппаратную приёмку. `reviewed=true` относится к разбору source-рецептов. Общие проверки не удалены: boot не arm, torque/motion не включаются автоматически, нужен owner/lease и явный arm; I/O ошибки прекращают запуск. Диагностические presets `stm32-debug`, `stm32-release`, `stm32-board8-plan` остаются uncommissioned.

## Сборка и запись одной командой

Из папки EUROBOT_NEXT на Mac или Ubuntu:

```sh
python3 tools/install_robot.py build
```

Это собирает `build/stm32-robot2026/firmware/eurobot_next.{elf,hex,bin,map}` и manifest и проверяет образ без USB-доступа. Для записи после подключения ST-LINK:

```sh
python3 tools/install_robot.py flash
```

Скрипт сам пересобирает текущий профиль, проверяет manifest/векторы, выбирает единственный ST-LINK, проверяет MCU/Flash, сохраняет всю старую Flash в `backups/`, записывает образ и выполняет независимое чтение для сравнения. При любой ошибке останавливается без повтора. При нескольких ST-LINK используется `--stlink-sn НОМЕР`. Защита/RDP/optionbytes не меняются, запись начинается по source standalone адресу0x08000000. Цель после записи оставляется halted — никакого автоматического запуска механизмов. При кастомном bootloader этот сценарий не подходит.

## Подключение

Подробная таблица: [BOARD_WIRING.md](BOARD_WIRING.md).

1. Использовать штатное питание работавшей платы; питание механизмов на первом этапе отключить. Подписанные входыGND/+6V/+12V не соединять друг с другом. Питание логики от+5Vадаптера/выводаST-LINK не придумывать.
2. ST-LINK USB→Mac; к маленькому SWDнадMCU: GND→GND,SWCLK→SWCLK,SWDIO→SWDIO,NRST→NRST. Если программатору нужен VTref, это подтверждённая точка3.3V; на показанномSWD её нет.
3. После записи и ручного reset подключить USB-UART3.3V к верхнему USART1: TXадаптера→RXплаты, RXадаптера→TXплаты,GND→GND. +питания адаптера не подключать. Связь115200,8N1.
4. Проверить только чтение:

```sh
python3 tools/board_test.py --port /dev/cu.usbserial-YOUR_ADAPTER
```

Проверить `armed=false`, ошибки и реальные GPIO до разрешения нагрузок. Если внешние PCA/приводы ещё не подключены, startup может показывать I/O fault и не разрешать arm; диагностические запросы и servo_probe остаются доступны. Не устранять ожидаемое отсутствие устройств обходом проверки. Порядок соединений обмоток L6474 и физическая связь правогоDIO сUSART3 на изображениях не подписаны; не подменять их разъёмом USART2. Сохранить существующий рабочий жгут2026 или проверить цепи перед новой сборкой.

## Единственный неразрешённый основной AX ID

Все доступные текущие копии2026 задают firstmain254/112.254 — broadcast. В локальной Git истории до19ff8a4 был ID98, но текущий cursor уже98; такая подстановка создала бы конфликт. Остальные известные адреса используются без требования заново собирать всю конфигурацию.

Новый `servo_probe` читает только model/firmware/individualID/EEPROManglelimits/currentrawposition/torquestate/returnlevel. Он не пишет регистры, не arm и доступен в диагностическом образе без commissioned profile:

```sh
python3 tools/servo_inventory.py --port /dev/cu.usbserial-YOUR_ADAPTER
```

Инвентаризация сканирует индивидуальные IDs1…253, исключая broadcast. Записывает `artifacts/servo-inventory.json`; отсутствие ответа одногоID не останавливает другие, потеря связи сSTM32 или malformed ответ прекращают весь обход. При активном owner/arm обход отвергается. Контроллер и шина servo должны иметь корректное питание; программа не включит его за пользователя. Модели и пределы представлены raw, без вымышленной привязки незнакомого устройства к механизму.

Когда конкретный физический main1 однозначно идентифицирован, его адрес можно внести без редактирования основного кода:

```sh
python3 tools/install_robot.py flash --primary-servo-id 42
```

42 здесь пример формата, а не найденный адрес. Значение должно соответствовать идентифицированному приводу. Скрипт создаёт приватный `config/robot_2026_local.hpp` и использует его при следующих запусках без повторного вводаID; существующие roleIDs и254 отвергаются. Пока этот адрес неизвестен, только операции main0/capture/prepare/release, затрагивающие его, отклоняются до любых выходных действий. Шасси, насосы, side/cursor/pinion/PCA и известные reserve-рецепты не блокируются из-за него.

Физическая запись в ходе разработки не состоялась: проверка USB на Mac19.10.2026 не нашла ST-LINK/STM32 candidates. После реального подключения доступность SWD и питания проверяются заново. Сборки и моки не выдаются за выполненную прошивку.
