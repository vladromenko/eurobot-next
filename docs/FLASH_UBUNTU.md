# Прошивка с Ubuntu

Для этой платы подготовлен заполненный source-профиль2026 и единый установщик: [ROBOT_2026_PROFILE.md](ROBOT_2026_PROFILE.md). Команда `python3 tools/install_robot.py flash` собирает его и выполняет backup/write/readback после подключения ST-LINK. Шаблон deployment вручную заполнять не требуется. Нижеприведённые команды общего `flash.sh` относятся к явно выбранному образу; без `--image` его default — диагностический Debug, а не рабочий source-профиль.

Актуальный пошаговый маршрут подключения, записи, ручного запуска и UART-проверки: [CONNECT_AND_FLASH.md](CONNECT_AND_FLASH.md). Образ должен соответствовать текущим исходникам и deployment; итоговые результаты сборки указаны в VALIDATION_REPORT. Старые или несогласованные образы отклоняются. Скрипт теперь проверяет `source_fingerprint` и доступность/хеш исходного deployment-профиля до USB-доступа. Mock-проверки загрузчика: **24/24 PASS**; они не подключаются к ST-LINK или плате.

Установить официальный STM32CubeProgrammer, Python 3 и ARM GNU Toolchain. Выполнить штатную установку USB/udev правил ST из комплекта CubeProgrammer по его инструкции и переподключить ST-LINK. Не запускать весь build/flash процесс через sudo; исправить доступ к конкретному USB устройству. Keil не нужен.

```sh
export STM32_PROGRAMMER_CLI="$HOME/STMicroelectronics/STM32Cube/STM32CubeProgrammer/bin/STM32_Programmer_CLI"
tools/build.sh stm32-debug
# Только локальная проверка файла и manifest, USB/SWD не открываются:
tools/verify.sh --image build/stm32-debug/firmware/eurobot_next.bin
```

До любого SWD соединения отключить питание двигателей/насосов и сверить распиновку платы/ST-LINK. Существующая прошивка может управлять механизмами при подключении debugger. Не выполнять приведённую запись без отдельного разрешения владельца робота:

```sh
# Разрешённая сверка с чтением target:
tools/verify.sh --image build/stm32-debug/firmware/eurobot_next.bin --allow-connect
# Разрешённая запись standalone приложения, после проверки загрузочной схемы:
tools/flash.sh --image build/stm32-debug/firmware/eurobot_next.bin \
  --allow-flash --confirm-no-custom-bootloader
```

`--allow-connect` имеет также имя `--probe`. `--stlink-sn <серийный_номер>` обязателен при нескольких ST-LINK. Неизвестный/неверный target, read protection, нехватка прав и отсутствие полного backup приводят к отказу без записи. Скрипт не исправляет защиту и не меняет загрузчик, чтобы обойти отказ.

## Что делает проверка

Без разрешающих флагов оба скрипта выполняют только локальную проверку: `.bin`, соответствующий `eurobot_next.manifest.json`, размер и SHA-256, ожидаемые ID/base/Flash, начальный SP в SRAM/CCM с выравниванием 8 байт, Thumb reset vector и все ненулевые ISR vectors (98 entries по CMSIS F407) внутри кода образа после таблицы векторов. Верхняя граница SP 0x20020000 допустима. Ни CLI, ни USB, ни SWD не открываются.

Manifest создаётся сборкой рядом с бинарным файлом; обязательные поля: `device_id` (`0x413`), `flash_base` (`0x08000000`), `flash_size` в байтах, `image_size`, `sha256`, `filename`, `source_fingerprint`, а для выбранного внешнего deployment — `deployment_source` и `deployment_sha256`. Header должен существовать и совпадать с содержимым при сборке; перенос проекта требует нового configure/build. Адреса допускают JSON integer или строку `0x...`. SHA не является цифровой подписью: проверяется согласованность локального результата сборки.

При явном подключении:

1. Перечисляется только ST-LINK (`-l st-link-only`), при нескольких нужен `--stlink-sn`; выбирается один serial на все операции.
2. Проверяется Device ID из ответа CLI и регистр DBGMCU_IDCODE `0xE0042000` (младшие 12 бит = `0x413`). Это семейство F405/F407, поэтому маркировка конкретного F407 на плате проверяется отдельно.
3. Читаются 2 байта `FLASHSIZE_BASE=0x1FFF7A22`; размер в KiB должен совпасть с manifest. Неизвестный ID/неполное чтение/неправильный размер останавливают работу.
4. Перед записью читается **вся внутренняя Flash** в `backups/flash-...bin`, сохраняется JSON с длиной, SHA-256 и адресом. При ошибке чтения или неверной длине запись запрещена. RDP не снимается. Скрипт не обещает получить копию защищённой прошивки.
5. Проверенный образ копируется в приватный временный каталог; вызывается запись только этого `.bin` по адресу приложения, проверка CLI и halt. Команда `-e all` не используется; CLI при обычной записи стирает только затрагиваемые сектора. Содержимое оставшейся части затрагиваемого сектора не обещается сохранить, поэтому сделана полная резервная копия.
6. Независимым чтением Flash сравниваются все байты образа и SHA-256. Отдельный verify делает это чтение без записи.

У каждой операции есть timeout (по умолчанию 60 с, допустимо 5..180). По тайм-ауту процесс CLI завершается, результат считается неизвестным, автоматического повтора записи нет. Локальный lock предотвращает одновременные операции этого инструмента с одним ST-LINK. Debugger/CubeIDE должны быть отключены; shared mode не включается.

Нет автоматического start/reset, массового erase, изменений option bytes, RDP, OTP или системного загрузчика. Это не гарантия, что старая или новая программа физически не запустится: питание приводов отключается отдельно до подключения и остаётся отключённым до стендовой приёмки. `--allow-flash` не заменяет отдельное разрешение владельца робота на реальную прошивку.

`--confirm-no-custom-bootloader` подтверждает, что область `0x08000000` предназначена для standalone приложения, а пользовательского bootloader там нет. По байтам backup это надёжно не определяется. При неизвестной схеме загрузки или пользовательском загрузчике запись запрещается до отдельного анализа и разрешения; изменять базу/manifest, чтобы обойти проверку, нельзя.

Backup охватывает только внутреннюю Flash: он не содержит option bytes, внешнюю EEPROM/Flash, RAM или состояние механики и не является проверенной процедурой восстановления. Копии могут содержать старые закрытые исходные данные/калибровки и исключены из Git через `backups/`.

## Фактически выполненные проверки

19.10.2026: 24 integration tests с **локальным mock CLI** прошли. Проверены offline default, отказ без подтверждения standalone приложения, SHA/vector checks, числовой manifest, backup до write, короткий/запрещённый backup, неверные ID/размер, отсутствующий/несколько ST-LINK, сообщение Error при exit=0, отказ записи без повтора, изменение образа после preflight, readback mismatch, standalone verify без write, timeout, missing/stale source fingerprint и отсутствующий/изменённый external deployment profile. Реальное оборудование не подключалось и не прошивалось этими тестами.

На Mac найден CubeProgrammer 2.23.0 внутри CubeIDE и выполнен только `-h`; это подтвердило синтаксис CLI, а не работоспособность USB/SWD. Команды соответствуют [STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html) и установленной справке. Адреса регистров проверены по [официальному CMSIS STM32F407](https://raw.githubusercontent.com/STMicroelectronics/cmsis-device-f4/master/Include/stm32f407xx.h), ID семейства — [RM0090](https://www.st.com/resource/en/reference_manual/dm00031020-stm32f405-407-415-417-437-455-469-application-note-stmicroelectronics.pdf).

```sh
python3 tools/tests/test_flash_tool.py -v
```
