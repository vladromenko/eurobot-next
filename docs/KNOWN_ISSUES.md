# Известные ограничения и ошибки

## Препятствия для полной готовности робота

| Пробел | Последствие | Что нужно для закрытия |
|---|---|---|
| Исходники2026 задают4 общие пары; назначение фактического жгута не установлено; новая разводка8пар PO1…PO16 отдельная | Программное назначение не доказывает существующую проводку/токи | Собрать по BOARD_WIRING и проверить каждый канал до нагрузки |
| Питание/токи/полярность клапанов неизвестны | Маска ПО не доказывает допустимость комбинации нагрузок | Проверка силовой части, предохранителей, ЭДС, общего тока и safe valve state |
| Неизвестны физические пределы шасси/stepper/servo | Тестовые значения нельзя применять наугад | Измерение хода, тока/скорости и знаков; отдельная конфигурация |
| Изменения после проверенного среза инвалидируют firmware fingerprint | Нельзя прошивать старый образ под новую конфигурацию | Свежий build и manifest; текущие проверки PASS приведены в VALIDATION_REPORT |
| Соединение со стендом/контроллером и HIL не выполнялись | Boot, электрика и физическая остановка не проверены | Стендовая программа HARDWARE/CHASSIS/PUMPS; все HIL статусы открыты |
| Права на приложение legacy не установлены | Оригиналы нельзя автоматически публиковать | Подтверждение лицензий/прав; legacy исходники за пределами нового репозитория |

Общий первый образ DIAGNOSTIC_MODE не выполняет внешних записей/автоопроса и не разрешает arm. Для OPERATIONAL_MODE требуется проверенная фактическая конфигурация; год старого образа её не выбирает.

В текущих исходниках реализованы локальное приложение кнопок и99s match state, gripper jobs, source-style stepper ramp/homing, операции обслуживания0…36 и опциональный debug UART5. Текущий срез прошёл host/sanitizers/ARM/ROS проверки. Протокол и ограничения приведены в [VALIDATION_REPORT.md](VALIDATION_REPORT.md) и [TESTING.md](TESTING.md). Все HIL статусы остаются открытыми.

Default deployment не разрешает arm: `commissioned=false`, неполные routes в базовом профиле, нулевые механические/силовые limits и непроверенные gripper bindings. Пример [legacy_2026_reference.hpp](../examples/legacy_2026_reference.hpp) сохраняет это состояние. Подтверждённые по исходникам IDs/геометрия/токи не доказывают установленное оборудование или допустимость этих токов. Неизвестные выводы, полярности, соответствие установленных моделей/ID source-профилю и power budget заполняются после проверки, а не случайными числами.

UART5 PC12TX/PD2RX115200 по умолчанию выключен. При разрешении он использует новый framed protocol и общего owner с USART1, а не прежний raw DebugTask. На присланной карте есть подписанный UART5 GND/RX/TX/+5V; подключение описано в BOARD_WIRING. Физическое подключение Dynamixel USART3/DIO остаётся неподтверждённым. Чтение application_state и raw GPIO различается; фильтрация выполняется с дискретностью Control10ms, без заявления о1ms измерении. Разрешённое обслуживание перечислено в [MAINTENANCE.md](MAINTENANCE.md).

Match timeout отключает communication; `communication --arg 1 --allow-maintenance` только возвращает приём команд, без arm. После ESTOP требуется новая явная arm procedure. BOARD_RESET сначала останавливает устройства и выполняется только после полной передачи ACK; потерянный ACK оставляет результат неизвестным и не вызывает автоматический повтор. Программный reset не гарантирует удержание груза: необходима проверенная механическая/силовая политика.

## Исправление ошибочной блокировки первого main

Прежний перенос требовал неизвестный второй адрес вместо254 и отвергал main0. Исходники, Git и две сохранённые AXF показывают действительную цель112 в SyncWrite. Теперь primary main выбирает только112 маской2, а completion читает112; main0/capture/release/prepare не требуют поиска другого адреса. Резервная пара1/2 сохранена. Подробные доказательства и проверки: [PRIMARY_GRIPPER_254.md](PRIMARY_GRIPPER_254.md).

Замечания обоснованы исходниками; их проявление на роботе не измерялось. Исправление новым кодом подтверждается тестом, электрическое поведение — аппаратной проверкой. Программный stop не заменяет аппаратное размыкание питания.

Критические fault handlers вызывают ограниченный локальный fail_safe; внешние UART-приводы не получают универсальной гарантии немедленного останова при CPU fault. Необработанный vendor IRQ может крутиться в Default_Handler до watchdog reset. Аппаратное отключение энергии обязательно проверяется отдельно.

Новый [board_8_pumps.hpp](../examples/board_8_pumps.hpp) уже задаёт все8 пар и независимые группы захватов; это предписанная новая разводка, без вымышленных текущих жгутов или значений мощности. GPIO/PWM/Stepper map используется аппаратным адаптером из единого board_connectors.hpp.

Рабочий [профиль2026](ROBOT_2026_PROFILE.md) уже содержит известные настройки и явную новую область программных команд, включая все8 маршрутов. Он не требует заново восстанавливать все параметры. Default диагностические presets по-прежнему не arm. Source-профиль проверяет явный arm и I/O startup; неисправный/отсутствующий обязательный узел не обходится. Отдельное испытание необходимо для измерения физических пределов, но их отсутствие в исходниках не оставляет автоматически пустыми все остальные поля.
