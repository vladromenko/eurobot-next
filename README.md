# EUROBOT NEXT

Новая платформа управления Eurobot на C++23 для STM32F407VG и ROS 2. Проект создаётся по восстановленной аппаратной карте прошивок 2025/2026; старое C-приложение не используется как новый прикладной код. Переносимое управляющее ядро поддерживает 1–32 насоса и клапана, обе реальные геометрии трёхколёсного omni-шасси, ограничения движения, arming, владельца управления, lease, тайм-ауты, ESTOP и проверяемый бинарный протокол.

**Это проверяемая программная платформа с открытыми задачами ввода в эксплуатацию. Аппаратная работоспособность всего робота пока не подтверждена.** По исходнику2026 подтверждены4 уникальных насоса; фактический жгут этой платы отдельно не проверен; для новой установки все8 пар назначены на PO1…PO16; существующую проводку сверяют по инструкции. Реализованы сценарии захватов финальной2026, finite motion, составные capture/release/prepare, локальное приложение кнопок и99s матча, а также типизированное обслуживание. Итоговые host/sanitizer/ARM и ROS проверки текущей редакции прошли; протокол — в VALIDATION_REPORT. Аппаратная проверка остаётся открытой. Навигация по полю и камера относятся к отдельному high-level приложению.

## Установка на общую платуSTM32F407

**Начать с [WHAT_I_NEED_TO_DO.md](WHAT_I_NEED_TO_DO.md).** Там приведены точные команды macOS, схемаSWD/UART, сохранение старойFlash, запись готовогоBIN и первые проверки. Плата одинакова для2025/2026; год прежней программы не определяет подключённые устройства.

Готовый комплект: `EUROBOT_NEXT_COMPLETE.zip`. Для первого запуска: `EUROBOT_NEXT.bin`, общий **DIAGNOSTIC_MODE** без движения, автоматического опроса и предположений о силовом жгуте. Исходники/ROS/скрипты и оба диагностических Debug/Release входят в `RELEASE_PACKAGE`. Владелец прошивает плату сам; подготовка комплекта не обращается к аппаратуре.

```sh
python3 tools/flash.py verify --image EUROBOT_NEXT.bin
# После подключенияSWD, проверки питания/standaloneFlash и сохранения backup:
python3 tools/flash.py flash --image EUROBOT_NEXT.bin --allow-flash --confirm-no-custom-bootloader
```

Для самостоятельной сборки без записи: `python3 tools/install_robot.py build` (общая диагностика по умолчанию). Рабочий2026-профиль выбирается только явно `--profile robot2026` и требует соответствующей фактической проводки; справочный [профиль2025](docs/ROBOT_2025_HARDWARE_PROFILE.md) не назначается по году прежнегоBIN.

Первый основной захват2026 использует112, резервный1/2; бывший слот254 неактивен. Все его сценарии реализованы с проверкой обратной связи. Разбор: [PRIMARY_GRIPPER_254.md](docs/PRIMARY_GRIPPER_254.md). В диагностическом образе запуск любого захвата запрещён до установки отдельного проверенного операционного профиля.

## Что находится в проекте

- `firmware/include/eurobot` и `firmware/src`: собственное C++ ядро и драйверы; сторонние CMSIS/FreeRTOS отделены в `firmware/third_party`.
- `ros2_ws/src`: типизированные интерфейсы, UART bridge и bringup. Lease/sequence/arming проверяются в контроллере, поэтому исчезновение ROS не оставляет исполнительные механизмы под прежней командой.
- `tests`: host проверки с имитацией транспорта и ошибок; это проверки алгоритмов и протоколов, а не замена аппаратных драйверов в прошивке.
- `tools`: сборка, тестирование, загрузка/проверка образа, аудит исходников и публикационного дерева.
- `docs`: аппаратные доказательства, архитектура, сборка, протокол, ограничения и полный реестр 603 legacy-функций.

Основой поведения служит финальная2026;2025 — база и явный исторический fallback. Сценарии реализованы через bounded Engine с отдельными job ID, accepted/running/result/cancel и категориями evidence. В отдельном рабочем source-профиле известные настройки заполнены автоматически; первый main использует112, резервный —1/2; неактивный слот254 не участвует в передачах и проверках. Новые программные ограничения и исходные параметры перечислены раздельно, физические пределы не объявляются измеренными. При boot исполнительные механизмы не вооружаются. Приложение сохраняет состояния13 кнопок, click/hold events, стратегию и match timer, но запуск матча требует явной authority. Дополнительный UART5 выключен по умолчанию; при его разрешении используется общий с USART1 owner/lease. Полная таблица37 сервисных операций: [MAINTENANCE.md](docs/MAINTENANCE.md).

Инструкции: [установка](docs/INSTALL.md), [сравнение2025/2026/NEXT](docs/COMPARISON_2025_2026_NEXT.md), [все сценарии захватов](docs/GRIPPER_SCENARIOS.md), [куда подключать каждый провод по карте платы](docs/BOARD_WIRING.md), [как прошить](docs/CONNECT_AND_FLASH.md), [проверка платы с Mac после самостоятельной прошивки](docs/MACOS_BOARD_TEST.md). `tools/board_test.py` по умолчанию только читает status/sensors; физическое упражнение требует явных параметров и флага. Все действия с реальной платой запускает владелец отдельно; разработка не подключалась к контроллеру. Для нового среза используйте свежие образ и manifest.

## Начало работы

Нужны CMake≥3.25, Ninja, GoogleTest, компилятор C++23 для host и ARM GNU Toolchain для STM32. Версии и команды: [CMAKE_BUILD.md](docs/CMAKE_BUILD.md). Стандарт C++26 проверяется отдельной целью, основным остаётся C++23.

```sh
cmake --preset host
cmake --build --preset host
ctest --preset host
cmake --preset stm32-debug
cmake --build --preset stm32-debug
```

Профиль по умолчанию намеренно uncommissioned. [legacy_2026_reference.hpp](examples/legacy_2026_reference.hpp) отделяет подтверждённые source facts от TODO_UNKNOWN и также не разрешает arm. Перед активацией реального оборудования нужно задать подтверждённый профиль: все используемые каналы насосов/клапанов, допустимые токи и комбинации, реальные пределы шасси, модели/ID сервоприводов и полярности входов. Незаданные подключения и нулевые пределы должны блокировать управление. Для новой разводки8+8 используйте [board_8_pumps.hpp](examples/board_8_pumps.hpp): все насосы и клапаны назначены на PO1…PO16, захваты получают отдельные группы. Это заготовка под описанное подключение с незаданными аппаратными limits. Не копируйте тестовые ограничения как безопасные пределы робота.

Сначала запускаются host тесты и проверка образа. Загрузка на STM32 возможна только после отдельного разрешения владельца. Option bytes, RDP и полный erase автоматически не изменяются. Инструкции: [FLASH_MACOS.md](docs/FLASH_MACOS.md), [FLASH_UBUNTU.md](docs/FLASH_UBUNTU.md).

## Насосы и безопасность

`select` выбирает изменяемые каналы, `values` задаёт их новое состояние; то же для клапанов. Одно изменение проходит единую проверку и одну транзакцию latch, без временного включения всех насосов. Количество каналов настраивается до 32, ограничение мощности — отдельно. Поля requested, commanded/known и measured/known различаются: SPI ACK не доказывает вакуум или ток. Подробности: [PUMPS.md](docs/PUMPS.md).

После старта исполнительные механизмы запрещены. Новая сессия должна получить lease и явно выполнить arm. Потеря связи, истечение команды или ошибка вызывают остановку и снятие armed; reconnect не восстанавливает прежнее движение. Программный ESTOP дополняет аппаратное отключение энергии.

## Происхождение и публикация

Оригиналы 2025/2026 остаются вне нового проекта. Права на их приложение неизвестны; они не включаются в публикацию. Сторонние зависимости должны сохранять лицензии и закреплённое происхождение. Автоматический аудит проверяет явные секреты, дословные копии legacy Core, наличие notices и неизменность справочных файлов:

```sh
python3 tools/audit_sources.py --legacy-root ..
python3 tools/audit_sources.py --publication
```

Результаты публикационного аудита и требуемое решение владельца: [PUBLICATION.md](docs/PUBLICATION.md), [LICENSE-STATUS.md](LICENSE-STATUS.md). Аудит не выдаёт юридическое разрешение. Лицензию собственного нового проекта выбирают после проверки прав; сведения о GitHub-публикации и её фактическом результате указываются отдельно, без предположения, что репозиторий уже создан.
