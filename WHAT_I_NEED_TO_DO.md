# EUROBOT NEXT — что подключить и какие команды вводить на Mac

## 1. Что готово и какой файл устанавливать

Плата STM32F407 одна и та же для 2025/2026. Год ранее установленного образа **не определяет проводку**, адреса устройств или комплект механизмов. В NEXT сохранены функции обеих версий;2026 остаётся основой полного функционала. Профили годов — восстановленные варианты параметров, а не обнаружение оборудования.

Для **первого подключения** использовать `EUROBOT_NEXT.bin` из корня проекта либо `RELEASE_PACKAGE/firmware/EUROBOT_NEXT.bin`. Это Release-образ **DIAGNOSTIC_MODE** общей платы: движение, насосы, клапаны и изменение регистров внешних устройств заблокированы даже при запросе arm. Автоматического поиска устройств/движения нет; диагностика не требует подключённого PCA, BMS или двигателей. Локально выходы приводятся в отключённое состояние. Физическое отсутствие импульсов/переключений после подачи питания всё равно проверяется с отключёнными нагрузками.

`EUROBOT_NEXT_COMPLETE.zip` содержит весь комплект: `source/` с CMake/исходниками/ROS2/tools/tests/examples, `firmware/` с актуальными BIN/HEX/ELF/MAP и manifest, `docs/` и журналы. ZIP не записывается в контроллер. BIN — содержимое внутренней Flash. HEX — альтернативное представление адресов/данных; ELF/MAP — отладка и состав программы. `firmware/debug/` содержит диагностическую Debug-сборку; по умолчанию устанавливается Release из `firmware/`.

Реализованы шасси/Maxon/энкодеры/одометрия, Dynamixel AX/MX, PCA/PWM/DC, L6474/профили шагов/home, насосы/клапаны 8/16/32 логических каналов, захваты/сценарии 2026 и отдельные 2025, кнопки/матч, диагностика, UART/RS485/SPI/I2C/DMA, watchdog, управление сессиями и ROS2. PID колёс выполняется внешними Maxon-контроллерами; проверенный библиотечный PID не выдаётся за их прошивку. Состав реальных ELF проверяется отдельно от наличия файлов. Число физических выходов платы 20;32-битные маски не создают дополнительные силовые линии.

Результаты текущих сборок: [VALIDATION_REPORT](docs/VALIDATION_REPORT.md), [FINAL_READINESS_REPORT](docs/FINAL_READINESS_REPORT.md). Физический SWD/Flash/UART/движение в ходе подготовки **не выполнялись**. Успешная программная проверка не означает испытание на роботе.

Пины MCU, карта разъёмов, протоколы и настройки исходников уже разобраны: повторно собирать их не нужно. Нужны только факты о реальном экземпляре и нагрузках. Неизвестные сведения блокируют соответствующий этап, а не подготовку файлов.

В базовом 2025 нет доказанной карты четырёх пар насосов. Четыре общие пары подтверждены 2026. Новые восемь независимых пар PO1…PO16 — отдельная назначенная разводка. Эти варианты не взаимозаменяемы. Для сохранения существующего жгута меняют профиль маршрутов; для восьми независимых пар нужны восемь реальных насосов/клапанов, проводка и подходящее питание. Подробности: [карта 2025](docs/ROBOT_2025_HARDWARE_PROFILE.md), [сравнение](docs/COMPARISON_2025_2026_NEXT.md), [разъёмы](docs/BOARD_WIRING.md).

## 3. Что подключить

Нужны ST-LINK с USB-кабелем для записи Flash, USB-UART с уровнями **3.3 V** для команд после установки, соединительные провода и штатное питание логики платы. Для MacBook с USB-C потребуется переходник с передачей данных.

1. Отключить питание колёс, насосов, клапанов, сервоприводов и шаговых двигателей. Закрепить механизмы, которые могут упасть при снятии тока. Сохранить работавшую схему питания логики. Карта не определяет, какая силовая шина питает её стабилизатор; подавать питание наугад нельзя.
2. К маленькому разъёму **SWD над STM32** подключить ST-LINK по подписям: GND→GND, SWDIO→SWDIO, SWCLK→SWCLK, NRST→NRST. На показанном разъёме нет VTref. Если ваш ST-LINK требует VTref/T_VCC, нужен отдельно подтверждённый узел 3.3 V; это вход измерения напряжения программатора, а не питание всей платы.
3. Подать штатное питание логики и подключить ST-LINK к Mac. Учитывать возможную подпитку через сигнальные кабели. Не подавать 5 V на SWD/USART и не ориентироваться на номера контактов другого типа ST-LINK.
4. Для команд после прошивки использовать верхний **USART1**: TX USB-UART→RX платы, RX адаптера→TX платы, GND→GND. Провод питания адаптера оставить неподключённым. Скорость новой прошивки 115200,8N1. ST-LINK по SWD не заменяет этот UART.

Не соединять+6 V и+12 V между собой. POx — коммутируемый минус нагрузки. Плакат платы и полные таблицы находятся в [BOARD_WIRING.md](docs/BOARD_WIRING.md). Красная обводка на изображении не задаёт назначений.

## 4. Терминал: подготовить инструменты

Открыть Terminal. Для уже подготовленного проекта выполнить:

```sh
cd /Users/vladromenko/Desktop/Eurobot/EUROBOT_NEXT
python3 --version
```

Нужен Python3.10 или новее. **Для записи готового BIN компилятор, CMake и Docker не нужны.** Установить [STM32CubeProgrammer от ST](https://www.st.com/en/development-tools/stm32cubeprog.html). На этом Mac программа найдена по следующему пути:

```sh
export STM32_PROGRAMMER_CLI='/Applications/STMicroelectronics/STM32Cube/STM32CubeProgrammer/STM32CubeProgrammer.app/Contents/MacOS/bin/STM32_Programmer_CLI'
test -x "$STM32_PROGRAMMER_CLI" && echo 'CubeProgrammer найден'
python3 tools/prepare_board.py list
```

Если CLI не найден, заменить путь на фактическое место установки. Команда `list` только перечисляет ST-LINK, не соединяясь с MCU. Ожидается один серийный номер. Ноль — проверить USB-кабель и переходник. Несколько — далее добавить `--stlink-sn РЕАЛЬНЫЙ_НОМЕР`.

**При работе из распакованного ZIP** перейти в его `RELEASE_PACKAGE/source`. Например, для комплекта в папке проекта:

```sh
cd /Users/vladromenko/Desktop/Eurobot/EUROBOT_NEXT/RELEASE_PACKAGE/source
```

Оттуда инструменты остаются по пути `tools/`, а готовая прошивка находится в `../firmware/EUROBOT_NEXT.bin`. Ниже команды для обоих вариантов приведены отдельно.

## 5. Проверить MCU и сохранить прежнюю Flash

Выполнять при отключённых нагрузках, подтверждённом питании и закрытых CubeIDE/debugger:

```sh
python3 tools/prepare_board.py inspect --allow-connect
python3 tools/prepare_board.py backup --allow-connect
```

Это уже обращение к реальной плате, но без записи Flash. Проверяются семейство 0x413 и размер 1MiB; отдельно сверить маркировку корпуса. Показываются option bytes через **display-only** команду `-ob displ`, включая RDP, если его выводит CLI. Никаких присваиваний option bytes скрипт не отправляет.

Успешный backup создаёт BIN размером **1048576 байт** и JSON с SHA256 в `backups/`. Скопировать оба файла в отдельное место до записи NEXT. Год старой программы для процедуры сохранения не важен; у произвольного образа нет универсального поля версии. Старый UART-протокол может быть несовместим с новым `board_test.py` до установки NEXT.

При отказе чтения или защите остановиться. **Не выполнять read-unprotect, изменение RDP, mass erase или запись option bytes:** они могут уничтожить старую Flash. Дамп содержит только внутреннюю Flash; внешняя память, option bytes и состояние механики в него не входят. Это не гарантия полного восстановления робота одним файлом. Backup не следует переименовывать и выдавать за новый образ с manifest.

## 6. Проверить и записать готовый образ

Условия: известна схема питания/SWD, проверен MCU, сохранён полный backup и подтверждено standalone-приложение по адресу **0x08000000** без собственного bootloader. При другом размещении нужен отдельный разбор; разрешающий флаг не является обходом этой проверки.

**Из исходной папки проекта:**

```sh
cd /Users/vladromenko/Desktop/Eurobot/EUROBOT_NEXT
python3 tools/flash.py verify --image EUROBOT_NEXT.bin
python3 tools/flash.py flash --image EUROBOT_NEXT.bin \
  --allow-flash --confirm-no-custom-bootloader
```

**Из `RELEASE_PACKAGE/source` распакованного комплекта:**

```sh
python3 tools/flash.py verify --image ../firmware/EUROBOT_NEXT.bin
python3 tools/flash.py flash --image ../firmware/EUROBOT_NEXT.bin \
  --allow-flash --confirm-no-custom-bootloader
```

Первый `verify` проверяет только файлы, SHA256, векторы и профиль. Команда `flash` повторно проверяет MCU, делает ещё один полный backup, записывает проверенный BIN и независимо читает его обратно для сравнения. Ожидаемый результат — `Independent readback matches image`.

При ошибке нет автоматического повтора. Скрипт не снимает защиту, не меняет option bytes, не запрашивает full erase и не запускает программу автоматически. Затрагиваемые записью секторы Flash могут стираться, поэтому backup обязателен. После успеха процессор оставлен **halted**; отсутствие ответа UART в этот момент нормально.

## 7. Запустить только логику и проверить UART

Силовое питание механизмов оставить отключённым. Завершить сеанс программатора, снять питание логики, отсоединить SWD при снятом питании, затем снова подать питание логики. Это ручной запуск. BOOT0 должен соответствовать штатной загрузке из Flash; его физическое расположение на плакате не задано. Не менять option bytes.

Подключить USB-UART по этапу 3 и найти имя порта:

```sh
python3 -c 'import glob; print("\n".join(sorted(glob.glob("/dev/cu.*"))))'
```

В следующей строке заменить имя **реально найденным портом вашего адаптера**:

```sh
export EUROBOT_PORT='/dev/cu.usbserial-ИМЯ_ВАШЕГО_АДАПТЕРА'
python3 tools/board_test.py --port "$EUROBOT_PORT"
python3 tools/board_test.py --port "$EUROBOT_PORT" --maintenance deployment_info
python3 tools/board_test.py --port "$EUROBOT_PORT" --maintenance board_info
python3 tools/board_test.py --port "$EUROBOT_PORT" --maintenance diagnostic_text
python3 tools/board_test.py --port "$EUROBOT_PORT" --maintenance gpio
```

Ожидается `mode="diagnostic"`, `profile="CUSTOM"`, `commissioned=false`, `armed=false`, нет активного владельца. Диагностический текст содержит `fw=0.1.0` и `DIAGNOSTIC`. `valid=false` в `deployment_info` означает незаполненный операционный профиль и в этом образе ожидается; это не ошибка связи. Непрочитанные данные батареи/позы/устройств остаются неизвестными. Уникальный идентификатор конкретного BIN — SHA256 manifest; версия 0.1.0 сама по себе не является уникальным хешем сборки.

Нажать проверяемый концевик рукой без приводов и повторить `gpio`: должен измениться соответствующий электрический бит. Общая диагностика не задаёт подтяжки по догадке; плавающий вход требует проверки схемы до homing.

В **DIAGNOSTIC_MODE** команды arm, torque, насосов, home и сценариев отвергаются. Команды переключения в OPERATIONAL_MODE нет: нужен отдельный проверенный профиль и новая сборка. Ожидаемый отказ arm нельзя исправлять отключением защиты.

## 8. Явно проверить подключённые устройства чтением

После подтверждения конкретной шины и питания можно выполнить отдельные запросы. Они не включают питание или torque. Например, известные из разных справочных профилей адреса AX:

```sh
python3 tools/servo_inventory.py --port "$EUROBOT_PORT" --ids 102 103
python3 tools/servo_inventory.py --port "$EUROBOT_PORT" --ids 1 2 7 8 13 16 25 98 112
python3 tools/board_test.py --port "$EUROBOT_PORT" --maintenance wheel_ticks
```

Списки — альтернативные исходные настройки, а не обещание наличия всех устройств. Выбирать список по установленным приводам и подтверждённой шине, а не выполнять оба вслепую. Timeout одного устройства не доказывает его отсутствие; потеря связи с STM32 или malformed-ответ прекращают обход. ID254 не запрашивается как индивидуальный servo. Другие выборочные чтения — в [MAINTENANCE.md](docs/MAINTENANCE.md). Автоматического периодического опроса внешних устройств в диагностическом образе нет.

## 9. Что необходимо до движения

Сверить фактические выходы, адреса, питание, полярности, свободный ход и ограничения. Закрепить робота и проверить независимое от MCU/компьютера отключение энергии. Создать отдельный профиль с **OPERATIONAL_MODE**, `commissioned=true`, только проверенными allowlists/routes и допустимыми диапазонами. Для сценариев требуется review задействованной механики. Это настройка по результатам проверки, а не простое изменение одного флага.

Профили 2025 и 2026 — исходные варианты. Ни один не становится автоматически правильным от того, что такая программа когда-то стояла на этой плате. После создания собственного проверенного `config/deployment_local.hpp` команды будут такими:

```sh
python3 tools/install_robot.py build --profile custom --config config/deployment_local.hpp
# После проверки выбранного профиля — отдельная запись:
python3 tools/install_robot.py flash --profile custom --config config/deployment_local.hpp
```

Этот local-файл намеренно не заполнен случайными значениями. До его создания команда откажет. `install_robot.py flash` без параметров всегда собирает общую диагностику и не подхватывает прежний 2026-профиль молча. Для явно подтверждённой комплектации 2026 существует `--profile robot2026`.

Пошаговые процедуры для 12 областей: [HARDWARE_VALIDATION_PLAN.md](docs/HARDWARE_VALIDATION_PLAN.md). Опробовать по одному шасси/колёса/энкодеры/AX/PWM/stepper/лифт/захваты/насосы/клапаны/сценарии/ROS2. Клиент завершает упражнение ESTOP и освобождает сессию. После снятия тока stepper теряет reference: отдельный вызов home с последующим ESTOP не позволяет считать лифт привязанным в новой сессии. Для home+move нужна проверенная последовательность в одной сессии с подтверждением состояния; фиксированное ожидание её не заменяет.

## 10. Если требуется пересобрать прошивку

Для готового BIN этот этап не нужен. Для сборки нужны CMake≥3.25, Ninja, Python, Git и ARM GNU с C++23. Для host tests также нужен GoogleTest. На этом Mac ARM toolchain автоматически находится в STM32CubeIDE; при другом месте установки задать `ARM_TOOLCHAIN_BIN` каталогом реальных `arm-none-eabi-gcc/g++/objcopy/size`. Keil не требуется.

```sh
cmake --version
ninja --version
bash tools/dependencies.sh
cmake --preset stm32-diagnostic-debug --fresh
cmake --build --preset stm32-diagnostic-debug --parallel
```
